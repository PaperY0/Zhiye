# 角色主题与拼音辅助设计

## 目标

为知野四类角色建立统一、可持续扩展的视觉主题，并为学生端与家长端提供固定的拼音辅助阅读体验。学生端同时增加轻量学习陪伴 IP，帮助山区儿童理解当前任务并保持学习连续性。

## 范围

- 学生端所有主要页面：使用用户提供的图一作为背景，并显示中文下方的拼音辅助行。
- 家长端所有主要页面：使用用户提供的图三作为背景，并显示中文下方的拼音辅助行。
- 老师端、管理端所有主要页面：使用用户提供的图二作为背景，保持当前中文界面，不显示拼音。
- 统一角色壳层、侧栏、移动端导航、顶部标题、主要按钮、空状态和操作提示的展示策略。
- 学生端新增学习陪伴 IP 提示区域，复用项目已有视觉素材，不引入外部网络资源。

不在本次范围内：重新设计业务流程、修改 OCR/ASR/DeepSeek 链路、自动翻译动态题目内容、修改权限模型和数据模型。

## 设计方案

### 1. 角色背景

在 `RoleShell` 统一依据当前角色设置主题类或 CSS 变量：

| 角色 | 背景 | 视觉目标 |
| --- | --- | --- |
| 学生端 | 图一 | 明亮、亲和、带探索感，适合儿童学习场景 |
| 老师端 | 图二 | 安静、清晰、弱装饰，支持长时间工作 |
| 管理端 | 图二 | 与老师端统一，强调稳定和信息可读性 |
| 家长端 | 图三 | 温和、自然、可信，适合查看学习摘要和沟通 |

背景作为壳层底图，内容卡片保留足够不透明度和对比度，避免背景纹理干扰文字。背景资源放入项目 `src/assets/role-backgrounds/`，通过静态 import 使用，避免运行时依赖临时文件路径。

### 2. 拼音辅助组件

新增一个可复用的拼音文本组件，接口至少支持：

- 中文主文本；
- 拼音文本；
- 主文本和拼音的样式覆盖；
- 必要时隐藏拼音的开关。

学生端和家长端由角色上下文或壳层配置默认开启，老师端和管理端默认关闭。拼音显示在中文正下方，使用较小字号、较弱颜色和适当行高；主文本仍是视觉和无障碍阅读的第一信息层。

优先覆盖固定界面文案：侧栏导航、顶部产品名和页面标题、主要按钮、空状态、步骤提示、反馈提示和返回操作。数学题、学生姓名、AI 生成内容等动态内容不做未经确认的自动拆分；组件允许调用方显式提供拼音，避免错误标注。

### 3. 学习陪伴 IP

学生端增加一个不阻塞主任务的陪伴提示区域：

- 使用项目已有的风筝谷视觉素材作为陪伴形象或视觉锚点；
- 展示简短鼓励语和下一步行动，如“继续学习”“需要提示吗”；
- 学生端提示语同样使用拼音辅助；
- 不覆盖题目、录音、拍照答疑等主要操作；
- 不新增外部请求，也不把陪伴提示伪装成 AI 生成结论。

## 组件与数据边界

- `RoleShell`：负责角色主题、背景和拼音策略的统一注入。
- `PinyinText` 或同等命名组件：负责一组固定文案的双层排版和可访问性。
- 角色导航组件：改为使用拼音组件渲染学生端和家长端标签。
- 学生首页或共享壳层中的陪伴组件：只负责展示与导航，不持有业务数据。
- 固定文案拼音表：集中维护，允许后续补充；不改变原有中文 label，保证现有路由和测试选择器稳定。

## 错误与降级

- 背景资源加载失败时，退回现有渐变背景，页面仍可使用。
- 某个固定文案缺少拼音时，只显示中文，不显示错误或猜测拼音。
- 小屏幕空间不足时，拼音允许缩小或换行，但不得遮挡按钮和主要内容。
- 陪伴 IP 素材不可用时，显示纯文字提示卡，不影响学生完成任务。

## 验收标准

1. 学生端首页、拍照答疑、知识点学习、错题本、任务、消息、历史记录使用图一背景。
2. 家长端学习摘要、联系老师、历史记录使用图三背景。
3. 老师端和管理端页面使用图二背景。
4. 学生端和家长端的侧栏、顶部标题、主要按钮、空状态和操作提示均按组件显示中文与拼音两层文本。
5. 老师端和管理端不出现拼音辅助行。
6. 学生端能看到陪伴 IP 提示，且不遮挡主要操作、不产生额外网络请求。
7. 角色切换和路由切换后主题不会串台。
8. 现有单元测试通过，生产构建通过，并完成学生、家长、老师、管理四类页面的浏览器视觉检查。

## 实施顺序

1. 导入并整理三张背景资源，建立角色主题映射。
2. 新增拼音组件和固定文案拼音表。
3. 接入统一角色壳层、导航、顶部标题和主要公共文案。
4. 接入学生端和家长端主要页面文案。
5. 增加学生端学习陪伴 IP 区域。
6. 运行测试、构建和四角色浏览器验收，修复视觉或回归问题。
