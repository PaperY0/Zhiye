一页速览：知野替教师做了什么

输入：一节 40 分钟课堂的录音 + 一句补讲目标（如“根据这节分数课，为明天准备 5 分钟补讲”）。
执行：本地语音转写 → 提取带时间戳的课堂证据 → 归纳学习缺口 → 生成四项成果。
输出：学生复习卡、教师课堂报告、5 分钟补讲教案、3 题针对性练习，全部可编辑、可追溯。
门槛：教师确认并发布前，学生与家长看不到任何 AI 内容；课堂转写与教师报告永不公开。

为什么它是“智能体”而不是聊天机器人

它有明确目标（goal）、固定五步计划、可追踪的工具调用、真实的失败状态与单步重试，以及不可跳过的人工确认关卡。所有产出必须是结构化 schema，无效或无证据支撑的结果不能进入发布环节。

01 BACKGROUND

一、项目背景

教育数字化已解决“资源有没有”，尚未解决“课后个性化复盘有没有人做”。

1.1 政策与产业背景

国家教育数字化战略行动、智慧教育平台与“双减”政策先后落地，乡村学校的硬件与资源短板正在被补齐：一块白板、一根网线、一台笔记本已能进入课堂。但数字化的下半场是应用——把技术嵌进教师每天真实发生的工作流，而不是再增加一个需要学习的工具。

与此同时，生成式 AI 在 2024–2026 年迅速普及。乡村教师面对的矛盾非常具体：不用 AI，课后复盘做不完；直接用通用大模型，又不敢把课堂录音和学生照片交出去，也更不敢让模型直接对学生下结论。

1.2 乡村小学的真实约束

时间被切片

一名村小数学教师通常带 2 个以上班级，周课时 18–25 节。课后可用于个别辅导、批改与复盘的时间被压缩到每天 30–60 分钟，且常被行政事务打断。

学情靠印象

哪个知识点卡住、卡在哪一步，教师多凭记忆判断。缺少可回溯的证据，补讲选题只能“凭经验猜”，导致重复讲已经会的内容。

材料从零做

一次针对性补讲需要：定位卡点、写教案、找或编 3 道变式题。即便熟练教师也需 1–2 小时，且与本周本班实际错情脱节。

学生无人可问

课后学生遇到不会的题，家里无人能辅导，只能带到第二天。问题堆积到下周，知识点已断层。

1.3 生成式 AI 的机会与错位

通用聊天机器人能“回答问题”，但无法接管流程：它不会去听一节完整的课，不会把结论锚定到课堂原话，不会在教师确认前拦住发布，也不会在模型失败时告诉教师“是哪一步失败、能否只重试这一步”。把这些能力拼起来，才是一个能上岗的数字员工。

知野的选择是：让 AI 做草稿与取证，让人做决定。系统接管“录音—转写—证据—复盘—成稿”的重活，把“是否讲给学生”的判断权完整留给教师。

1.4 产品定位与赛事契合点

定位：面向乡村小学教师的课堂复盘数字员工。教师提交课堂录音与补讲目标，系统自主规划并执行课堂转写、证据提取、卡点归纳、补讲材料生成与交付；教师只在对学生或家长发布前审核。
iCAN AI 应用创新挑战赛关注点知野的对应设计
目标驱动，而非一问一答一次任务有明确 goal（补讲目标）与固定五步执行计划
工具调用可观测转写、证据提取、卡点归因、成果生成均为独立工具步骤，各有状态、摘要、耗时与错误
失败可恢复四类真实失败（无麦克风、空录音、无模型 Key、网络断开）保留已成功步骤，仅重试失败步骤
人机协同边界清晰教师确认是学生/家长可见内容的唯一门槛；AI 推断与课堂证据分区显示
儿童数据安全音频与题图只在本地处理，仅文本交给云端模型；密钥不进入浏览器；原始音频即用即删
02 PAIN POINTS

二、当前存在的痛点问题

七个痛点来自教师课后工作的真实时序，按“发生频率 × 单次耗时”排序。

#痛点具体表现直接后果现有方案的不足
P1课后复盘吃掉整块时间40 分钟课的转写、要点归纳、报告撰写需 20–30 分钟手工完成教师加班，或干脆不做复盘通用听转写工具只给文本，不给教学结论
P2学情判断缺证据哪个知识点、哪一步卡住只能凭印象补讲选题不准，重复讲已会内容在线组卷平台只有分数，没有过程证据
P3补讲材料从零制作定位卡点→写教案→编 3 道变式题，1–2 小时材料与本周本班错情脱节教辅题库按教材编排，不对应本班卡点
P4学生提问得不到及时回应课后无人可问，家长辅导能力有限问题堆积，知识点断层拍照搜题类 App 直接给答案，不引导思考
P5家长信息不对称家长只看到分数，看不到“卡在哪一步”家校沟通低效、焦虑传导班级群消息刷屏，无结构化摘要
P6儿童数据与内容安全风险学生语音、题图、姓名上传到不明服务学校与教师不敢用，家长不信任多数产品未做本地化处理与教师审核门槛
P7弱网与公用设备乡村网络不稳定，常用共用电脑上传中断、成果丢失纯云端工具断网即不可用

2.1 痛点的根因拆解

流程未被接管

复盘是一串动作，不是一次问答。工具只覆盖其中一环，剩下的手工环节依旧消耗教师整块时间。

结论未锚定事实

模型可以生成通顺的建议，但若不能回到“课堂上到底说了什么”，建议就无法被教师采信。

发布缺少门槛

面向儿童的内容一旦缺少人工确认，幻觉与不当推断会直接作用到学生身上。

2.2 知野的针对性回应

痛点知野的机制可验证结果
P1浏览器录音 → 本地 FunASR 转写 → DeepSeek 结构化成稿，一次执行交付四项成果教师只做审核与编辑，不做转写与归纳
P2课堂证据 EvidenceItem（原话 + 起止秒 + 来源）与推断 InferenceItem 分离存储每条建议可回到转写原话与时间点
P3根据卡点生成补讲教案与 3 题练习，可一键转为班级任务补讲材料与本班本课绑定
P4拍照识题 → 选择卡点 → 分层提示 → 复述 → 迁移题 → 错题本先提示后讲解，不给一步到位的答案
P5家长摘要由教师生成并确认后发布，仅含聚合指标不展示孩子完整提问与 AI 对话
P6ASR/OCR 本地运行，音频题图即用即删；密钥只在本机环境变量公开演示站无法调用本机 AI，也无密钥可窃
P7原型数据保存在浏览器，断网可继续编辑与查看；失败有中文原因与重试断网不伪装成功
03 REQUIREMENTS

三、需求分析与目标用户群体

从三个角色的真实一天出发，倒推功能边界。

3.1 典型场景

李老师 · 村小数学教师

下午第三节课讲“分数的基本性质”。放学后她打开知野教师端，点击“开始新课堂录音”（课堂音频投屏播放即可回采），输入目标“为明天准备 5 分钟补讲”。3 分钟后看到转写、证据、复习卡草稿与补讲方案；她把方案改成“用米尺和厘米尺做一次单位方向对照练习”，确认发布。

林晓雨 · 五年级学生

晚上写作业遇到单位换算题，打开“拍照答疑”，拍下题目，选择“卡在某一步”。系统先给提示，她复述思路后拿到一道变式题，题目自动进入错题本。她只看到老师发布的复习卡和自己的错题。

家长 · 监护人

周末打开“学习近况”，看到本周学到什么、主动完成的事、一条鼓励建议和老师的留言。看不到排名、同学对比，也看不到孩子和 AI 的完整对话。

6.3 智能体编排：RecapJob 五步契约

步骤输入输出失败行为
1 transcribe课堂音频（或文本）证据列表（原话 + 起止秒）无人声 → 任务失败，保留空结果并提示重录
2 extract-evidence证据列表校验后的证据列表转写为空 → 失败，不进入后续步骤
3 identify-gaps目标 + 证据学习缺口推断（必须引用证据 ID）目标为空或无证据 → 失败
4 generate-deliverables目标 + 证据 + 缺口四项成果（复习卡/报告/教案/练习）模型失败 → 仅此步失败，前 3 步保留
5 teacher-review四项成果教师确认后发布或下载未确认 → 学生端不可见
状态机：任务状态 queued → running → needs-review / failed；步骤状态 pending → running → succeeded / failed / skipped。重试规则：只允许重试 failed 步骤，上游成功结果作为输入复用——转写不会因为生成失败而重复执行，也不会重复计费。

6.4 结构化输出与防幻觉设计

机制实现拦住什么
严格 schema所有上下文模型 extra="forbid"；字段类型、长度、上下界显式声明模型自行加字段、把字符串写成数组
证据引用约束InferenceItem.evidence_ids 必须引用已存在的 EvidenceItem，否则 schema 拒绝没有出处的“建议”
纯文本闸门TextOnly 拒绝控制字符、data URL / http(s) URL、SVG 标记、base64 编码的图片字节提示注入与二进制夹带
业务规则校验测验恰好 3 题、答案必须是选项之一、判断题归一化为“正确/错误”；迁移题答案必须在选项内无法使用的题目草稿
低温与 JSON 模式temperature 0.2，response_format=json_object；prompt 明确“不得编造未出现的事实、不得诊断学生”发散与格式漂移

前端二次校验isCompleteLessonAnalysis 等类型守卫在渲染前逐字段检查不完整数据进入界面

6.5 安全与隐私设计

数据最小化

音频与题图只进本地服务，处理完立即删除临时文件；只有转写文本与上下文交给云端模型。日志不写题目图片、课堂原文与敏感反馈正文。

密钥隔离

模型 Key 只存在于本机 .env.local 或 Render 私密环境变量；浏览器只持有 VITE_ 公开参数，/health 只返回布尔值不泄露 Key。

来源与鉴权

AI 服务中间件校验 Origin 白名单；公网模式启用邀请码换取 HMAC-SHA256 签名令牌（8 小时），所有 AI 路由服务端验签。

速率限制

滑动窗口限流：全局 120 次/小时、单令牌 30 次/小时、邀请码兑换单 IP 10 次/15 分钟；超限返回 429 与 Retry-After。

儿童保护

保护性表达不作为普通消息发送，需人工确认后转交；风险案例仅展示最少必要上下文，不作诊断、不自动判断、不贴标签；处置全程写审计。

崩溃隔离

OCR 在独立子进程运行，原生崩溃不会拖垮 API；模型惰性加载，未配置 Key 时其他功能仍可启动。

6.6 失败边界（四类真实故障）

故障界面表现处理动作
无麦克风权限“无法访问麦克风：…” + 状态“处理失败”提供“重试录音”，不产生 AI 初稿
录音为空“没有录到有效课堂音频，请检查麦克风权限后重试。”请求根本不发出，节省算力与费用
未配置模型 Key“未设置 DEEPSEEK_API_KEY”转写仍可用；生成步骤失败并可重试
网络断开“本地 AI 服务未启动，请运行 start-local-ai.ps1”保留已成功步骤，恢复后仅重试失败步骤

7.1 教师端的三个设计坚持

一屏一件事

每个页面只有一个主操作：录音、审核发布、生成任务、查看洞察。次要操作收进抽屉或次级按钮。

student-companion学生消息、当前页面回复 + 拼音 + 页面跳转动作学生即时；禁止输出 URL
parent-summary可核实事实列表主题/鼓励/教师留言教师确认后家长才可见
student-inference事实与错题列表证据/观察/建议支持教师采纳后生效，禁止诊断贴标签

8.2 AI 是执行者，不是聊天窗

教师目标→ ① 转写工具→ ② 证据提取→ ③ 卡点归因→ ④ 成果生成→ 教师审核→ 发布 / 下载→ 学生结果回流

每一步都是可观测的工具调用：有状态、有摘要、有耗时、有错误码；失败只影响该步，已成功的转写与证据被保留并复用。这与“打开一个对话框提问”有本质区别——前者替代的是工作流，后者只替代了一次搜索。

8.3 三条防幻觉机制

① 事实与推断分区

课堂证据（原话 + 时间）与 AI 推断（带引用）在界面上分开显示；schema 强制推断必须引用已有证据。

② 只准依据给定上下文

prompt 明确“不得编造课堂事实、学生表现或学生标签”；教师偏好只能改变表达方式，不能覆盖课堂事实。

③ 人做最终判断

AI 只产出草稿；学生与家长可见的任何内容都必须经过教师确认，未确认即不可见。

8.4 本地优先的模型分工

环节模型为什么这样分工
课堂转写FunASR（本地）音频不出本机，带时间戳，可直接作为证据；CPU 可运行
题图识别PaddleOCR（本地）学生照片不进云端；子进程隔离避免崩溃扩散
结构化生成DeepSeek（云端）只接收文本与上下文，成本低、JSON 稳定，可随时切换供应商
可替换性：所有模型调用都封装在统一工具契约之后（transcribe_audio / extract_evidence / identify_learning_gaps / generate_deliverables），换成 Qwen、通义或本地开源模型不需要改动前端与业务流程。

9.5 学生操作流程（6 步）

步动作界面反馈与注意点
1首页看复习卡只出现老师已发布内容；没有则显示“目前没有新的复习卡”

角色流程

9.7 交互指南

状态一眼可读

课程：待开始 / 录音中 / 已暂停 / 处理中 / 处理失败 / AI 初稿 / 已发布。状态同时用文字与颜色表达，不只靠颜色。

没有假进度

处理中显示真实阶段（“正在调用本地 FunASR 转写，再交给 DeepSeek 生成复盘”），不显示无意义百分比。

失败给原因与出路

每个失败都伴随中文原因与“重试录音 / 仅重试生成”等明确动作；已成功步骤与成果保留。

删除可撤销

课堂、教案删除后通过页面通知可立即撤销，不做静默破坏。

拼音辅助

学生端左下角“拼音辅助 · 已开启”，可为界面与 AI 回复逐句标注拼音，适合低年级与识字量不足的学生。

无障碍

键盘可完成主要流程；AI 状态用 aria-live="polite" 播报；图标按钮带可读标签；可点区域 ≥44px。

9.8 常见问题与故障处理

现象原因与处理
“本地 AI 服务未启动”未运行 start-local-ai.ps1；或端口 8787 被占用
“未设置 DEEPSEEK_API_KEY”在 .env.local 填入 Key 后重启本地 AI 服务
“没有识别到清晰的人声”录音太短、太轻或环境噪音大；靠近音源重录
“题目文字不清晰，请重新拍摄”OCR 置信度 <0.65；在光线充足处正面拍摄整题
公开演示版无 AI公网站默认不提供 AI；本地运行或使用带邀请码的公网 AI 服务
换设备看不到数据原型数据只保存在当前浏览器；正式服务需数据库与账号（见 6.7）

十、应用前景与商业模式

10.1 应用前景

方向判断与依据
政策顺风教育数字化进入“应用深水区”，教师减负与因材施教是明确导向；乡村小规模学校的个性化辅导缺口最大

① 单机演示原型（当前）→ ② 邀请码公网演示→ ③ 2–3 所试点校（数据库 + 认证 + 授权）→ ④ 区域推广（教育局采购 / 公益合作）

11 RISKS & 12 CLOSING

十一、风险与合规 · 十二、结语

11.1 风险与缓解

风险影响缓解措施
尚无持久化后端与认证不能存放真实学生资料如实标注为演示原型；SPEC 与 Prisma/domain 契约已就绪，试点前完成接入
模型幻觉错误结论影响教学证据引用约束 + schema 校验 + 教师确认门槛 + 推断单独标注
录音与儿童数据授权合规与信任风险只用获准脱敏音频；本地处理、最小留存、审计留痕、即用即删
公网成本与滥用费用不可控邀请码 + 令牌过期 + 多层限流 + 可一键停用公网 AI
公网演示数据隔离访客误解为真实服务页面与文档明示“数据只在本浏览器、不跨设备”
教师采纳门槛功能闲置保留教师既有习惯：可编辑、可弃用、可只用手工整理；设置项可调节确认强度

12.1 结语

知野没有把聊天机器人塞进课堂，而是把“录音—转写—证据—复盘—审核—发布”这条教师每天都要走一遍的工作流整体接管。它用结构化契约约束模型的表达，用证据引用约束模型的依据，用教师确认约束模型的出口；失败时它说清楚哪一步坏了、能不能只修那一步。

这让 AI 在课堂里的位置变得清晰：做草稿、做取证、做重复劳动；把判断、取舍和面对学生的责任，留给教师。
