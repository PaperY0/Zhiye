# 知野课堂复盘数字员工：竞赛设计说明

## 目标

在 2026 AI杭州“AI+超级智能体”赛道中，将知野定位为一个可接管教师课后复盘工作的数字员工。教师提交课堂录音和补讲目标后，系统自主规划并执行课堂转写、证据提取、学习卡点归纳、补讲材料生成和交付；教师仅在对学生或家长发布前审核。

## 成功标准

- 用一段真实、脱敏的 1–2 分钟课堂录音，完整完成一次端到端演示。
- 用户可看见智能体理解到的任务目标、执行计划、工具调用状态、失败原因和重试入口。
- 每条关键教学建议均可回溯到课堂转写片段或学生作答数据；模型推断必须与事实证据区分显示。
- 一次执行至少交付四项可直接使用的成果：学生复习卡、教师课堂复盘报告、5 分钟补讲教案、3 题针对性练习。
- 成果经过教师确认后才能发布；演示中可下载一个可验收的补讲包。

## 范围

### 本次实现

1. `课堂复盘数字员工`任务执行页：展示目标、计划、步骤状态、工具输入摘要、耗时、错误及重试。
2. 编排链路：音频转写 → 课堂证据提取 → 卡点归因 → 复习卡/报告/补讲教案/练习生成 → 教师审核 → 发布或下载。
3. 现有本地 AI 服务继续承担 FunASR 转写、PaddleOCR 识题和 DeepSeek 结构化生成；将各调用封装为可追踪工具步骤。
4. 可下载补讲包，以及支持演示的成功、模型失败和转写失败状态。
5. 单一真实课堂场景：五年级数学“分数的基本性质”。
6. 可复现交付：恢复应用根依赖清单、锁文件、环境变量示例、启动说明和演示数据说明。

### 明确不做

- 新增家长端、后台、通用聊天、多人协作或第二个智能体。
- 未验证的外部搜索、自动发消息或任何无需教师确认的对外发布。
- 把课堂事实、模型推断和教师最终决定混在一起展示。

## 主流程

```text
教师上传录音 + 补讲目标
  → 智能体生成执行计划
  → 转写工具
  → 证据提取工具
  → 卡点归因工具
  → 补讲包生成工具
  → 教师审核与编辑
  → 发布给学生 / 下载补讲包
  → 学生练习结果回流为下一次补讲建议
```

## 任务与工具模型

- `RecapJob` 是一次可追踪执行，包含目标、输入、状态、步骤、产物和错误信息。
- `RecapStep` 固定为 `transcribe`、`extract-evidence`、`identify-gaps`、`generate-deliverables`、`teacher-review`；每步有 `pending | running | succeeded | failed | skipped` 状态和可读摘要。
- 工具返回必须符合结构化 schema。无效或缺少证据的结果进入失败状态，不得进入发布步骤。
- 教师可仅重试失败步骤；已成功步骤和已有成果保留。

## 证据与安全

- 课堂转写作为事实来源；建议卡显示“课堂证据”与“AI 推断”两个独立区块。
- 所有学生可见、家长可见的内容必须由教师显式确认。
- 演示录音、截图和提交材料只使用获得许可且已脱敏的数据；不提交 API Key、真实学生姓名或原始敏感音频。

## 演示验收

1. 教师输入“根据这节分数课，为明天准备 5 分钟补讲”。
2. 页面先显示智能体计划，再依次展示三类工具调用与输出。
3. 教师能展开两条转写证据，理解“为什么推荐补讲单位换算”。
4. 教师编辑一处复习卡后确认发布；下载补讲包。
5. 单独演示 DeepSeek 不可用或转写为空：系统清楚标出失败步骤，保留先前成果，并只重试该步骤。

## 非功能要求

- 页面适配 1440 × 900 路演屏幕，关键信息无需滚动才能看见。
- 全流程日志和演示数据应可在刷新后恢复或由明确的“重置演示”动作恢复。
- 根目录须具备可用的安装、启动、测试和演示说明；不得依赖未提交的 `node_modules`。
